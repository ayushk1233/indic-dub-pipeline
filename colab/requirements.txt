# Colab-side dependencies. Deliberately different from the repo's
# requirements.txt: this side only synthesizes, so it never loads IndicTrans2
# and is not bound by that file's transformers<4.47 pin.

# torch, torchaudio and torchvision are intentionally NOT pinned. Colab ships a
# mutually consistent, CUDA-matched set, and replacing it costs several GB and
# routinely leaves a torch that cannot see the GPU. The old pins here
# (torch 2.5.1 / torchvision 0.20.1) no longer resolve at all, because Colab
# has moved past the Python version those wheels were built for.

# TTS==0.22.0 is unusable now. It caps at Python <3.12, and Coqui is defunct so
# it will never be updated. This is the maintained idiap fork: same `TTS`
# import namespace, same XTTS-v2 checkpoint, tracks current torch. It requires
# transformers>=4.57, which is exactly why this file must stay separate from
# the repo's own pins.
coqui-tts==0.27.5

# coqui-tts declares transformers>=4.57 with no upper bound, and that is wrong.
# TTS/tts/layers/tortoise/autoregressive.py imports isin_mps_friendly from
# transformers.pytorch_utils, which exists in 4.57.x and was removed in 5.0.
# Colab preinstalls transformers 5.x, which satisfies the fork's declaration,
# so pip leaves it in place and `import TTS` then dies. Cap it ourselves.
transformers>=4.57,<5

soundfile
librosa>=0.10.0
einops

# numpy is squeezed from three sides here and the window is narrow.
#
#   transformers 4.57  needs >= 2.0   — it touches numpy.dtypes.StringDType
#   numba (via librosa) needs < 2.3   — hard version check, refuses at import
#   f5-tts 0.1.0       declares <= 1.26.4
#
# The first two leave exactly 2.1 <= numpy < 2.3. f5-tts cannot be satisfied
# alongside them at all, so its declaration is deliberately overridden: pip
# will print a conflict for it on every install and that is expected, not a
# failure. Its pin is a ceiling inherited from an older scientific stack
# rather than a measured incompatibility, and IndicF5 is exercised on numpy
# 2.2 to find out whether it is real.
#
# Getting this wrong is expensive to debug, because numpy 1.x breaks
# transformers *silently*: the lazy loader catches the AttributeError raised
# while building its torch-backed classes and drops those names, so
# `import transformers` succeeds, the version string looks right, and the only
# symptom is a missing GPT2PreTrainedModel reported from inside coqui-tts.
#
# Install this file *after* IndicF5 so these constraints are the surviving ones.
numpy>=2.1,<2.3
